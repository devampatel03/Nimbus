# Nimbus — MEMORY.md

## Architectural decisions

| ID | Decision | Rationale | Date | Alternatives considered |
|----|----------|-----------|------|------------------------|
| AD-1 | Postgres + Apache AGE for bi-temporal graph | Single DB to encrypt/backup; AGE gives graph queries without Neo4j ops burden | 2026-09-12 | Neo4j (ops), plain Postgres (no graph queries) |
| AD-2 | Gemini 3.8 Flash for tool execution only | $0.75/M input, strong tool calling, but 13.3s TTFT disqualifies it from Mode A | 2026-09-12 | Local-only (weaker tool calling), OpenAI (more expensive) |
| AD-3 | Scrubber as sole egress point | Privacy boundary must be architectural, not policy | 2026-09-12 | Per-tool sanitisation (too many surfaces) |
| AD-4 | Phone-first, no wearable hardware | Removes ~4 months from critical path; phone mic is sufficient for Phase 1-6 | 2026-09-12 | Omi fork (deferred) |
| AD-5 | `graph_node` minimal schema (id, entity_type, canonical_name, created_at) | TECHNICAL_ARCHITECTURE.md 6.1 only spells out `graph_edge`'s SQL; `subject_id`/`object_id` need something to reference | 2026-09-12 | Richer node schema (attributes/aliases) — deferred until a pod needs it |
| AD-6 | Contradiction detection (MEM-3) as a pure SQL self-join predicate, not an LLM call | Cheap, deterministic, always-on; `is_distinct_from` handles NULL objects, `coalesce(valid_to, 'infinity'::timestamptz)` handles open-ended intervals | 2026-09-12 | LLM-based contradiction judging (nondeterministic, costly, unnecessary for a pure interval-overlap check) |
| AD-7 | `MemoryManager` uses a `DeterministicStubEmbedder` (sha256-derived unit vector) instead of a real embedding model | No embedding model is wired into Nimbus yet — T1.5 only covers vLLM *generation* serving. An `Embedder` protocol makes this swappable without touching call sites | 2026-09-13 | Blocking T1.6/T1.7 on embedding-model integration (out of scope; would stall foundation-phase memory plumbing) |
| AD-8 | No per-user filter in Qdrant episodic queries | Nimbus is a single-user, self-hosted deployment (PRD section 1) — one instance holds one user's data, so collection-wide search is correct, not an isolation gap | 2026-09-13 | Per-user Qdrant payload filter (premature for a single-tenant product) |
| AD-9 | `graph_proximity` is always 0.0 for episodic (Qdrant) results in hybrid retrieval | Episodic chunks carry no entity links yet — that requires `EntityExtractor` output, which is stubbed (T1.6 built the interface only, not a working extractor) | 2026-09-13 | Embedding-time entity linking (deferred until extraction workers are real) |
| AD-10 | `trait_evidence` gets an ORM `id` primary key not present in TECHNICAL_ARCHITECTURE.md 7.1's literal SQL | ORM rows need a PK; the doc's SQL omits one for this table (unlike `user_trait`/`agent_stance`, which both specify `id UUID PRIMARY KEY`) | 2026-09-13 | Composite PK on `(trait_id, session_id, observed_at)` (rejected — an evidence excerpt isn't guaranteed unique per session+timestamp) |
| AD-11 | `check_friction` is a pure keyword/stance-overlap heuristic, not an LLM call | Runs inline in the same turn as the request; a cloud call here would violate INV-4 (Mode A never blocks on network), and no local model is wired in yet | 2026-09-13 | LLM-based conflict judgment (deferred to T3.6's full friction-mandate eval, which this session's `check_friction` does not attempt to satisfy) |
| AD-12 | `scrubber.execute_external(intent: ToolIntent, session_id: str)` takes a `session_id` not present in section 8.1's abbreviated signature | Needed to scope the per-session entity-ref store (SCR-3: refs "resolved after response returns"); `session_id` is a local routing parameter, carries no memory/transcript/reasoning content, so does not weaken INV-2 | 2026-09-13 | A module-level "current session" context var (rejected — implicit global state is harder to test and to reason about under concurrent sessions than an explicit parameter) |
| AD-13 | `pii_detector.py` uses regex/heuristics (no spaCy/NLP dependency) for named-entity detection | Same constraint as AD-7/AD-11: no NLP/ML dependency wired into Nimbus yet, and the check must be deterministic, dependency-light, and fast enough to run inline on every egress call. False negatives here are a privacy leak; false positives just block one tool call — so every category is tuned toward high recall over precision | 2026-09-13 | spaCy/Presidio (rejected for this session: new heavy dependency requiring model download + licence/CVE review, not requested) |
| AD-14 | The orchestrator's `act` node executes every tool call via `tool.run(...)`, not by building a `ToolIntent` and calling `scrubber.execute_external` itself. `CalendarTool.run` (the only tool needing a third-party service) calls the scrubber internally; `TasksTool.run` (purely local) never does | Section 8.2's pipeline and section 9's `act` description don't specify which layer owns the scrubber call for a multi-tool registry; putting it inside each tool keeps `act` tool-agnostic (it doesn't need to know which tools are "cloud" vs "local") while keeping INV-1 satisfied transitively — `act` never imports a transport library itself | 2026-09-13 | `act` building `ToolIntent`/calling the scrubber directly for every tool regardless of whether it needs cloud reasoning (rejected: would force a network round-trip for a purely local operation like creating an internal task, which the "internal task store" framing explicitly rules out) |

- mypy strict-mode gotcha: setting `[tool.mypy] python_version = "3.11"` restricts mypy's own *parser* to 3.11 syntax for every file it walks, including third-party stubs — this broke on `numpy` 2.5.x stubs which use PEP 695 `type` statement syntax unconditionally. Fix was to drop the explicit `python_version` pin entirely (let mypy infer from the running interpreter, which is 3.14 in this project's `.venv`), not to add per-module overrides or `exclude` patterns (both were tried and didn't work — `follow_imports = "skip"` doesn't prevent the stub file from being parsed).

- pytest needs `pythonpath = ["."]` under `[tool.pytest.ini_options]` in `pyproject.toml` for `from src....` / `from config....` imports to resolve in test modules under `tests/unit/` (no root `conftest.py` exists to do this implicitly).

- 2026-09-12/13 (T0.10/T2.9): `uv sync` (no `--extra dev`) silently uninstalls all dev dependencies (pytest, mypy, ruff, pre-commit, detect-secrets, ...) if you only need to add one prod dep (alembic here) — always use `uv sync --extra dev` in this repo.
- pytest-asyncio 0.24+ gotcha: a session-scoped async fixture (e.g. an `AsyncEngine`/`create_all`+`drop_all` fixture in `tests/conftest.py`) combined with `@pytest.mark.asyncio` test functions that default to a function-scoped event loop causes `asyncpg` errors like "cannot perform operation: another operation is in progress" or "attached to a different loop." Fix: set both `asyncio_default_fixture_loop_scope = "session"` **and** `asyncio_default_test_loop_scope = "session"` under `[tool.pytest.ini_options]` — setting only the fixture scope is not sufficient.
- SQLAlchemy `Mapped[datetime]` columns default to `TIMESTAMP WITHOUT TIME ZONE` unless the column is explicitly given `DateTime(timezone=True)` — Postgres+asyncpg then rejects tz-aware Python `datetime` values with "can't subtract offset-naive and offset-aware datetimes." Since all this schema's timestamps are `datetime.now(UTC)`-produced, every `DateTime` column across `src/memory/schemas/*.py` needs an explicit `DateTime(timezone=True)` (aliased as a module-level `_TZ` constant); the Alembic migration already had `timezone=True` correctly, so this was strictly an ORM-model bug, not a migration bug — the two are hand-written separately in this repo (no autogenerate was available) and can drift.
- `GraphRepository.find_contradictions`'s self-join uses `a.id < b.id` purely to dedupe symmetric pairs; since `id` is a random `uuid4`, this ordering has no relationship to insertion order. Tests asserting a specific `(edge_a.id, edge_b.id)` tuple order are wrong — assert the pair as an unordered `frozenset` instead.
- `tests/conftest.py`'s session-scoped `pg_engine` fixture (`create_all` at setup, `drop_all` at teardown) manages schema independently of Alembic migrations against the same real Postgres instance. This is intentional (fast, isolated test schema vs. the deployment-path migration) but means the DB's `alembic_version` table can end up out of sync with actual table existence after a test run — if you need to hand-verify a migration afterward, expect to `DROP TABLE alembic_version` (or drop/recreate the DB) before re-running `alembic upgrade head` to get a clean, consistent state.

- 2026-09-13 (T3.1/T3.4/T3.5): a naive AST scan for PSA-1 ("no code path writes the character card") that only looks for the literal string `"character_card.md"` inside a write-call's subtree is insufficient — it misses `CHARACTER_CARD_PATH.write_text(...)`, where the literal only appears once, at the constant's own definition site, not at the call site. Verified this gap directly: injected `CHARACTER_CARD_PATH.write_text("oops")` into `agent_character.py` and the literal-only scan passed (false negative). Fix: also flag any write-call whose subtree contains an `ast.Name`/`ast.Attribute` referencing `CHARACTER_CARD_PATH` by name, not just the literal path string. Re-verified the fixed scan catches the same injection. Any future AST-based "don't write path X" check in this repo should search for both the literal and the named constant that holds it, not just the literal.
- Simple substring/keyword heuristics for detecting semantic conflict (used in `check_friction`'s goal-negation branch) need stemming, not exact word match — `"exercise"` is not a substring of `"exercising"` (the `e` at the end of "exercise" doesn't appear at that position in "exercising"). - Verified PSU-1 (`ProfileManager.save_trait` rejects a trait with no evidence) and the stance-reversal detection (`StanceLog.record_stance` sets `revised_from`) per the manual's "prove the test can fail" rule: removed the evidence-empty guard (test failed, though with a different exception than the guard normally raises, since `max()` on an empty generator errors first) and removed the reversal condition (test failed with an exact assertion mismatch), then restored both.
- 2026-09-13 (T3.9/T3.11-T3.13, scrubber): a naive phone-number regex built from fixed digit groupings (`\d{3}-\d{3}-\d{4}`) misses non-US groupings like UK's `+44 7700 900123` (4-3-3). Fixed with a permissive candidate regex (any digit/separator run of sufficient length) filtered by total digit count (7-15) in a separate `_looks_like_phone` check — but that permissive regex then false-positived on ISO date fragments inside the scrubber's own serialized payloads (e.g. the `"2026-09-15"` part of a calendar param's `"2026-09-15T15:00:00+05:30"`, which has 8 digits and separator-only characters between them, landing inside the same 7-15 digit window as a real phone number). Fixed by explicitly excluding candidates that fully match `^\d{4}-\d{2}-\d{2}$` before the digit-count check. Any future loose numeric-pattern PII detector in this codebase should check it against ISO 8601 date/datetime params first, since those are common, legitimate, and easily confused with phone-shaped digit runs.

- A naive smoke test of the DESTRUCTIVE risk gate produced a false "it didn't reject" reading: the test message ("delete my meeting") contained the word "meeting", which the `think` node's keyword heuristic treats as a *calendar-create* trigger, silently overwriting the test's manually-assigned `tool_calls` before `act` ran — and a `unittest.mock.AsyncMock(return_value=...)` fixed return value doesn't care what it was actually called with, so the test "passed" for the wrong reason.
